What this redesign throws out from the current sheet

  • Dotted underlines + dashed top rules on every split row. Already an editorial idiom (aeonDottedUnderline, aeonDashedTopRule) — but used everywhere at once, they fight each other and add noise. Each direction here uses one divider grammar consistently.
  • The 8sp uppercase micro-labels. "TOTAL BUDGET" / "ALLOCATED" / "OVER LIMIT" at 8sp with 1sp letter-spacing become unreadable. Replaced with H-standard 10sp 2.4-letter-spacing eyebrows used once per region.
  • The 2dp gauge. Visually accidental. Style A uses a 1–3px hairline that lights up only when filled; Styles B/C use a 4px / 2dp track but only one per sheet, not per row.
  • Inline raw TextField for the amount. Replaced visually by a mono-tabular readout that matches EntryAmountDisplay, so the amount keeps the same typographic weight whether typed or displayed.
  • "CONFIRM SPLIT" button height tied to buttonCornerRadius * 2. That's a coupling bug — button height should come from dims.buttonHeight, not the corner radius token.
  • Twin equal-weight primary actions. Revert (destructive-ish) and Confirm (primary) are weighted equally. Here, Revert is ghost; Confirm carries the accent — and the 1 : 1.4 column ratio makes the hierarchy unambiguous.

Recommendation

  • Style A for parity with AeonSelectionSheet + maximum editorial restraint.
  • Style B if the team wants the split sheet to read as a peer of AeonImpactHeaderCard (best for visual hierarchy when many splits).
  • Style C if you anticipate growing per-split metadata (planned date, tag, recurrence) — the grouped-field surface scales best.
